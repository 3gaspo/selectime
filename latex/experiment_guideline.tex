\section{Question and scope}
Test whether validation can combine frozen foundation-model input scopes and
retrieved covariates on Adaptime's 90 dataset/frequency/term tasks with its four
dataset exclusions. Chronos-2 reports univariate and multivariate baselines,
task and item/variate scope selectors, task and item/variate scope mixtures,
fixed-alpha scope ridge, and top-$K$ mixtures for
$K\in\{1,5,10,15,20\}$. TS-ICL reports univariate and the five top-$K$
mixtures. Chronos-Bolt reports univariate only. Raw top-$K$ forecasts are
intermediate mixture inputs. Self-augmentation, broad selectors over all
candidates, and direct-horizon transfer are excluded.

\section{Windows and retrieval}
The official TIME test length and horizon $H$ define test windows. Validation
origins walk backward from the first test origin at stride $H$ and the same
phase, capped by both the requested validation length and the official test
date count. The default requested validation length equals the test length.
Scope ridge uses exactly these windows as fitting rows; there is no additional
training interval.

A validation row is usable only when its available target history and $H$-step
future each contain finite support. Unusable rows never reach a backbone and
contribute no loss. Validation retrieval ends before validation starts; test
retrieval ends before test starts. Neighbor futures are finite, wholly before
the applicable boundary, and available before the query. No test observation
enters either datastore.

Use instance-normalized Euclidean lookback distance with at least 80\% finite
overlap. Require complete maximum-$K$ support and reuse ordered prefixes for
smaller $K$. Rescale retrieved histories and observed futures to query units
using lookback-only statistics. All-series scope is the default; same-series
scope remains an explicit ablation. Datastore caps are optional and disabled
by default.

\section{Hard scope selection}
The hard selectors compare univariate and multivariate validation forecasts by
per-date MSSE. Task selection averages variates within each date; per-variate
selection scores each item/variate separately. Use the paired moving-date-block
bootstrap one-standard-error rule with 1000 replications by default. The
automatic block length is the larger of rounded $N^{1/3}$ and
$\lceil H/s_{\rm val}\rceil$, capped at $N-1$. Prefer univariate within the
admissible set. No usable date selects univariate; one date uses the observed
minimum. One run seed controls backbone stochasticity and bootstrap sampling.

\section{Mixtures and scope ridge}
For each win-frequency mixture, compare univariate and one alternative on
eligible validation rows. Exclude alternative fallback rows and non-finite
losses. With $w$ alternative wins among $n$ rows, counting ties as one half,
freeze
\[
p=\frac{1+w}{2+n},\qquad
\widehat y=(1-p)\widehat y_{\rm uni}+p\widehat y_{\rm alt}.
\]
No usable row gives $p=0$. Scope weights are fitted once per task or per
item/variate; each top-$K$ weight is fitted once per task.

For task-level scope ridge, let
$d=\widehat y_{\rm multi}-\widehat y_{\rm uni}$ and
$r=y-\widehat y_{\rm uni}$. For finite target cells $j$, use MSSE weight $a_j$,
the reciprocal of the row's observed-future count times its seasonal scale.
With configured but unvalidated $\alpha=1$,
\[
p=\frac{\sum_j a_jd_jr_j}{\alpha+\sum_j a_jd_j^2},\qquad
\widehat y=\widehat y_{\rm uni}+pd.
\]
Do not clip $p$. No usable fitting row records an unfitted vanilla fallback
with $p=0$. Freeze every choice or coefficient before test.

\section{Execution and artifacts}
Hydra configuration is \path{src/timebench/conf/experiment.yaml}; task settings
are \path{src/timebench/config/datasets.yaml}; the entry point is
\path{src/scripts/run_selectime.py}. The Chronos-2, TS-ICL, and Bolt launchers
are respectively \path{scripts/submit_experiment.sh},
\path{scripts/submit_ts_icl.sh}, and
\path{scripts/submit_chronos_bolt.sh}. The scheduler first prepares data, then
extracts and predicts validation windows, calibrates the controls, extracts and
predicts test windows, assembles the controlled forecasts, evaluates them, and
builds the report.
Forecast stages finalize canonical vanilla before dependent candidates.

Products live under \path{outputs/selectime/<backbone>/}. Every stage allocates
a schema-1 configuration-addressed manifest before work. Fully written tasks
become \texttt{computed}; a successful scheduler step finalizes them as
\texttt{completed}. Exact completed work is reused and interrupted tasks restart
from their beginning. Reports retain consumed manifests, metric coverage,
fallbacks, hard-choice counts, mixture weights, and ridge support. Assembled
methods have no independently measured inference latency.

\section{Verification and evidence}
The focused regression module is
\path{src/tests/test_selectime_contract.py}. It covers chronology, retrieval,
hard scope selection, task/per-variate mixtures, scope ridge, lifecycle, and
report contracts without foundation inference. Run a narrow remote smoke before
the complete study. Existing result documents describe earlier configurations;
fresh runs are required for this reduced reported method set.
